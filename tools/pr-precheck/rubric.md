# Rubric: is this pull request ready to submit?

Each check judges the outcome, not the write-up. The checks map to the four failure families: silent drift (checks 1-2), not tested (3), unreviewable (4-5), standards wall (6-8).

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff matches plan | Every changed file and hunk in the diff, read against the plan's files, steps, and "not in scope" list, plus its deviation notes (live: `## Deviations` in plan.md). | Every changed file and hunk is something the plan names or a deviation note explains; nothing the plan scopes out is touched (no new flag, option, setting, rename pass, or rewrite of another function); and every step the plan promises is in the diff, or its absence is disclosed in a deviation note or the description. Fail on any unplanned, undisclosed hunk beyond the fix, even a small adjacent one, and on a planned step that is missing with no disclosure. | required |
| Description matches diff | The PR description's claims about what changed ("implements the plan exactly", "docs updated", "no changes outside X", "adds tests for Y"), each read against the diff and the commit list. | Every claim of coverage or fidelity is supported by something in the diff. Fail if the description claims more than the diff delivers (a promised docs update or test that is absent) or claims fidelity ("exactly as planned", "nothing else changed") that the diff contradicts. A shortfall the description states plainly ("X deferred, see plan") passes. | required |
| Decisive test evidence | The test-evidence section, read against the plan's test plan and the repro's own steps: which command was run, on which path, and what it printed before and after. | The evidence re-runs the repro the plan names, on the path the fix changes, and shows an observable before and after (the failing output, then the expected output the plan states). Every failure mode or repro step the plan puts in scope is exercised, unless the plan or description defers it. Any test the PR adds exercises the fixed behavior, not an unchanged path. Where the plan's test plan or the repo's docs name checks to run (test suite, lint, typecheck), their outcomes are shown; a check reported failing with its reason still counts as evidence. Fail on "tested locally", "tests pass", or "works on my machine" with nothing named, on evidence that exercises the unchanged path, and on a named in-scope failure mode that is never re-run. | required |
| No debris in the diff | Added and removed lines of the unified diff, and the commit messages. | The diff contains no debug output (print, eprintln, console.log, DEBUG logging), no commented-out code or abandoned first attempts, no dead or unused functions or imports added, no TODO or FIXME left on the change, and no formatting, re-indent, or re-ordering hunks unrelated to the fix. One real, in-scope fix with nothing riding along passes. Fail if any of these is present. | required |
| Change is reviewable | The diff's hunks and the commit list taken together: can a reviewer find the fix and trust the rest? | The fix is visible as the bulk of the diff and every other hunk is a necessary part of it (a test, a doc line, a changelog entry). Fail if mechanical churn (re-printed identical lines, import restructuring) or unrelated hunks bury the fix, or if the commit messages show unfinished work ("wip", "misc cleanups while debugging"). | required |
| Repo template and checklist honored | The repo-facts block (live: `.github/PULL_REQUEST_TEMPLATE.md` and `docs/CONTRIBUTING.md`): each section or ask the repo states, read against the description and the diff. | Every ask the repo states is met with real content or the matching file in the diff: the template's sections filled, `Closes #<issue>` present, required checklist items true, a required changelog or whatsnew entry present in the diff, tests added when the repo asks for tests with behavior changes. Fail if a stated ask is visibly skipped, left as boilerplate, or ticked but contradicted by the diff. Pass if the repo states no template or asks. | required |
| AI-use disclosure | The repo's stated AI policy (repo-facts block; live: CONTRIBUTING.md and the template, where the course always requires disclosure under Notes for Reviewers) read against the description. | Where the repo or course asks for AI-use disclosure, the description contains one, in the author's own words, saying that AI was used and how. Fail if the policy requires disclosure and the description has none. Pass if the repo states no AI policy and the template has no disclosure ask. | required |
| Maintainer direction engaged | The issue thread (the bundle's thread highlights; live: the issue page), looking for explicit maintainer instructions or open questions about the fix. | Where a maintainer gave an explicit instruction or asked a direct question about the fix, the PR follows it or the description addresses it. Fail if the PR contradicts or ignores such direction. Pass if the thread holds none. | preferred |
| Title names the change | The PR title, read against the diff. | The title states the change in a few words and matches what the diff does. | preferred |

## Verdict rule

Accept if and only if every `required` check passes. Reject if any `required` check fails. Treat `unclear` as `fail`: a claim that cannot be verified from the package is not ready to submit. `preferred` checks are reported in the summary but never change the verdict.

A shortfall that the plan's deviation notes or the description honestly discloses does not fail "Diff matches plan", "Description matches diff", or "Decisive test evidence" on its own; being less than everything is not a reason to hold. A shortfall that is silent does fail them.
